# 面试讲解与可能问答

## 30 秒介绍

“ForgeLite 把 coding agent 拆成模型规划和本地执行两层。模型通过原生 tool calling 选择读、写、替换或运行命令；我用 Python 标准库自己解析这些调用，并在固定工作区执行，再把结果回传模型，直到模型给出最终文本或达到回合上限。它不依赖任何 agent 框架。为了控制上下文，我做了时间历史压缩和按最近访问淘汰的 LRU 工作记忆。”

## 可能问题

**模型为什么需要 tool calling，而非让它输出 shell 文本？**

tool calling 给每个操作明确的名称和 JSON 参数 schema。程序可以逐项校验、记录 `tool_call_id` 并回传对应结果，模型也更容易在失败后修正。文本解析则容易混淆解释、代码块和命令。

**如何保证模型不会访问工作区外的文件？**

先把工作区和请求路径都做 `resolve()`，再用 `candidate.relative_to(root)` 判断祖先关系。绝对路径、空路径和 `../` 穿越会返回错误。这个检查在真正每一个文件工具内执行，不依赖模型遵守 prompt。

**命令工具安全吗？**

它提供的是降低误操作风险的工程约束，并非安全隔离：工作目录固定、命令输出和时间有限制、明显灾难性模式会拦截。但 shell 本身能力很强，恶意模型仍不应被授予生产机权限。因此实际使用必须给 disposable workspace，并可进一步改为容器/权限受限子进程。

**上下文压缩为什么还需要 LRU？**

历史压缩解决“很早以前发生什么”；LRU 解决“现在最可能继续使用什么”。编码任务常反复修改少量文件，LRU 用文件路径作为 key 刷新访问时间，容量满时删最久未用项。它保存短观察而不是完整文件，降低 token 占用；最终编辑前再读文件保证正确性。

**什么时候停止？如果模型一直调用工具怎么办？**

无 tool call 且有 assistant 文本时正常结束；达到 `max_steps` 时硬停止并说明可能有部分改动。网络、参数或工具错误以 tool result 送回模型，使模型通常能调整下一步，而不是让程序异常退出。

**如何证明不是封装现成 agent？**

可从 `src/coding_agent` 逐个展示：`client.py` 用 `urllib` 发 HTTP，`agent.py` 是显式 while/for 控制循环，`tools.py` 是全部本地工具，`history.py` 与 `lru_memory.py` 是自主上下文管理。依赖列表也只有打包工具，没有 agent 框架或 SDK。

**你如何验证 agent 可以从空目录完整交付，而不是只会修改已有代码？**

我有两层证据。第一层是不联网的端到端控制循环测试：模拟模型依次请求写实现、写测试、写 README、运行 unittest，验证本地工具编排。第二层是真实 `openai/gpt-oss-120b`：它在 7 个回合内从空目录创建待办应用、测试与 README；第一次命令失败后，下一回合自行修正，5 项测试通过。我又独立黑盒验证了 add/list/done 与错误退出码。结构化轨迹在 `docs/evidence`，视频也使用这次真实结果。

**真实演示中有失败吗？为什么这反而重要？**

有。第一次 `run_command` 返回 `ok=false`，控制循环没有崩溃，也没有把失败当成功，而是把工具错误作为对应 `tool_call_id` 的结果回传。模型下一回合改变命令并得到 `ok=true`。这证明 agent 是“观察—行动—反馈—修正”的闭环，而不是一次生成固定脚本。

**为什么本地网关要特殊处理代理？**

桌面系统可能全局设置 `HTTP_PROXY/HTTPS_PROXY`。普通 `urllib` 会继承它，导致 `127.0.0.1` 请求错误地送往代理并返回 502。客户端解析 base URL；只有 `localhost`、IPv4/IPv6 loopback 使用空 `ProxyHandler` 直连，远程 API 仍服从系统网络配置。这个判断有独立单测。

**历史压缩怎样保证 API 消息仍合法？**

不能按单条消息粗暴切片，因为可能保留 `role=tool` 却删掉引入它的 assistant `tool_calls`。ForgeLite 把一条工具调用消息和后续全部工具结果组成原子组，再按组选择最近历史；测试会检查任何保留的 `tool_call_id` 都有对应父调用。

**Low、Medium、High 是不是只改了 UI 标签？**

不是。三档分别设置不同的本地 system instruction、默认最大模型回合与上下文字符预算；显式 `--max-steps` 或环境变量仍可覆盖。这样实现不依赖某个厂商专有的 `reasoning_effort` 参数，在 OpenAI 兼容网关间更可移植。

**审计日志为什么不直接保存完整 prompt 和命令输出？**

完整内容更容易复盘，但可能包含源码、业务数据或密钥。`--audit-log` 只保存 UTC 时间、事件名、工具名、参数键、成功状态、输出长度和终止原因；足以重建执行流程，同时降低视频和日志泄密风险。
